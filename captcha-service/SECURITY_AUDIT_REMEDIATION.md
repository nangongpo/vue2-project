# captcha-service 等保整改记录

## 已落实的应用整改

- 输出 JSON 结构化安全事件，包含时间、服务实例、环境、操作码、结果、原因码、耗时、限流和依赖状态。
- `traceId`、`requestId`、`attemptId`、账号主体使用带密钥哈希的脱敏值；IP 仅保留网段；不记录 User-Agent。
- 不记录 ServiceSecret、HMAC 签名、CaptchaToken、验证码答案、完整滑动轨迹或 Redis Key。
- backend 将验证码调用结果写入统一 `sys_audit_log`，复用现有审计日志详情、导出和完整性校验能力。
- 现有审计页增加验证码操作码筛选：`captcha.*`。

## 必须由部署和运维平台落实

- 日志集中采集，留存不少于六个月；最终期限按定级、行业监管和客户基线确定。
- 日志存储使用追加写入、访问控制、定期备份和防篡改机制；应用数据库审计记录使用 `AUDIT_INTEGRITY_SECRET` 校验完整性。
- 审计查询只授予审计/安全角色，导出权限单独授权；禁止普通业务管理员查看敏感审计详情。
- 所有主机、容器、数据库和日志平台接入统一时间源并校验时钟偏差。
- 对以下条件配置告警：服务认证失败激增、验证码失败率激增、限流激增、Redis 不可用、异常来源网段、审计写入失败。
- 生产环境注入独立且至少 32 位的 `CAPTCHA_LOG_HASH_SECRET`，不得与 `CAPTCHA_SERVICE_SECRET` 共用。

## 验收证据

- 抽查 JSON 日志，确认不存在 Token、签名、答案、轨迹、Redis Key 和完整 User-Agent。
- 在 backend 审计页按每个 `captcha.*` 操作码查询并导出，确认结果、时间、脱敏标识和耗时可追溯。
- 修改一条审计记录后执行完整性校验，确认校验失败。
- 模拟 Redis 故障、非法签名和异常来源，确认日志、审计记录和告警均产生，且验证码默认拒绝。
- 提供日志平台留存策略、备份策略、权限矩阵、时间同步和告警规则截图/配置作为测评材料。
