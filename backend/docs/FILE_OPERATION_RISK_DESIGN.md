# 文件管理接口风险分级设计

日期：2026-11-12。状态：现有文件接口的动态分级已实现；新增应急、批量、永久清除及高保障认证能力的边界见第 9 节。

## 1. 设计原则与现状

风险由数据敏感度、业务可用性影响、能否恢复、是否解除安全隔离和操作规模共同决定。L0～L3 是本项目内部操作分级，不等同于等保等级或 OWASP ASVS 验证等级。

高安全基线要求最小权限、逐请求授权、强认证、职责分离、可追溯和失败关闭。审批用于控制高影响操作；普通查询和无业务影响的可恢复操作不全部升级为 L3。

调整前的实现事实（用于说明本次变更背景）：

- 管理列表、扫描历史、文件审计为 L0，详情为 L1，重扫为 L2，拒绝、删除、恢复为 L3。
- 四类管理写操作均固定进入审批，重扫标为 L2 也会创建审批。
- 删除仅标记 DELETED 并取消扫描，不物理删除内容；存在恢复入口。
- 重新扫描会把文件改为 QUARANTINED/PENDING，扫描通过后可改为 READY。因此可能中断已关联文件使用，也可能使已拒绝文件重新可用。
- 恢复会清除删除标记，进入隔离扫描；通过后恢复可用。
- 现有风险 Guard 主要根据操作码判断，尚未统一按目标关联关系和安全历史动态分级。
- 人工拒绝当前同样写入 INFECTED，不能仅凭该字段区分病毒命中与人工封禁；自动恢复之前必须补足拒绝来源及解除依据。

本次实现同时调整目录基线、目标决策、审批分支和安全来源模型，不只降低目录中的风险值。

## 2. 等级与控制

| 等级 | 适用影响 | 必须控制 |
| --- | --- | --- |
| L0 | 当前用户自己的最小化进度信息 | 登录、所属关系校验、限流、必要访问和异常日志 |
| L1 | 管理范围内的常规元数据查询 | 管理员 MFA 登录、接口/数据范围/字段授权、访问审计、分页与防枚举 |
| L2 | 单文件可恢复管理变更、敏感信息读取 | L1 控制，五分钟内重新认证和 MFA；写操作必须有原因、幂等键和原子审计，无常规事前审批 |
| L3 | 影响已有业务、解除安全封禁、大规模或不可逆操作 | L2 控制，目标绑定的事前审批、独立审批人、执行时重新授权与风险检查、结果复核 |

管理身份未绑定 MFA 时拒绝 L2/L3 操作，不能退化为仅密码验证。高保障部署应支持抗钓鱼认证；密码加 OTP 不能描述为已经达到最高身份认证保障。

L3 至少要求申请人与审批人不同；解除安全封禁、永久清除另要求执行人与申请人不同、复核人与执行人不同。每个角色分别检查权限，禁止以角色名称代替授权。

## 3. 现有管理接口目标矩阵

下表路径均以 `/api/v1/files` 为前缀。管理读取不返回文件内容，管理权限不授予业务下载权限。

| 方法与路径 | 操作码后缀（system.file.） | 默认等级 | 升级条件/限制 |
| --- | --- | --- | --- |
| GET / | admin.read | L1 | 文件名、归属和业务引用可能敏感；仅返回列表所需字段 |
| GET /:fileId | admin.detail | L1 | 读取受限安全详情等敏感字段升 L2，仍需字段权限 |
| GET /:fileId/scan-jobs | admin.scan-history.read | L1 | 仅任务概要与状态，不返回内部调度信息 |
| GET /:fileId/scan-jobs/:jobId | admin.scan-history.detail | L1 | 申请人信息、原因等按字段权限脱敏；受限调查详情升 L2 |
| GET /:fileId/scan-jobs/:jobId/attempts | admin.scan-history.attempts | L1 | 脱敏执行摘要；原始诊断必须专门授权并升 L2，绝不返回凭证和物理路径 |
| GET /audit | audit.read | L2 | 包含操作人员、原因及前后快照，分页查询、独立审计权限；默认不提供原始全量快照 |
| POST /:fileId/rescan | admin.scan | L2 | 已关联业务或存在未解除拒绝/病毒记录时 L3 |
| POST /:fileId/reject | admin.reject | L2 | 当前可用且已关联业务，普通人工拒绝升 L3；已拒绝文件重复操作返回明确状态，不覆盖原安全依据 |
| POST /:fileId/delete | admin.delete | L2 | 单个、未关联的软删除；存在业务关联升 L3；保留/调查锁定时直接禁止 |
| POST /:fileId/restore | admin.restore | L2 | 单个、未关联且能证明删除前为正常可用的文件；有关联、拒绝/病毒历史或历史不完整时 L3 |

所有读取均只允许范围内对象。UUID、租户、父文件、任务的所属关系逐层检查；无权对象不得通过错误消息泄露其存在。

字段敏感等级与操作风险分别计算。响应先选择用户有权读取的字段，再按实际返回字段决定是否升级；不要因为数据库存在高敏字段，就使所有列表和历史查询弹出验证。

## 4. 写操作场景细化

### 4.1 删除

| 场景 | 决策 |
| --- | --- |
| 未关联、可用文件，单个软删除 | L2 |
| 未关联、已拒绝或病毒文件，单个软删除 | L2；继续保留原始内容和安全证据，不解除封禁 |
| 有任意业务关联，单个软删除 | L3，审批明确受影响业务；保留关联记录，不自动解绑 |
| 保留锁定、调查证据、依法不得销毁 | 禁止删除；审批不允许绕过锁定 |
| 关联状态或保留状态无法确定 | 拒绝执行，待状态明确后重新决策 |
| 批量软删除、永久清除 | L3，需独立权限与接口；当前未提供这两类接口 |

“未关联”必须由后端查询全部真实业务引用判定，不能使用前端 bindings 数组长度。业务集成必须保证引用集中登记；未完成引用治理前，不对可能存在外部引用的文件自动降级。

### 4.2 拒绝与应急隔离

未关联文件人工拒绝为 L2；影响在用文件的普通人工拒绝为 L3。发现正在传播的恶意文件时，等待事前审批不适合应急处置。

新增独立的应急隔离能力（尚未实现）：限定安全响应权限、L2 强认证、强制事件编号与原因、立即隔离、告警通知、独立事后复核。不得通过通用 reject 请求中的客户端布尔值绕过审批。扫描 Worker 自动隔离恶意文件属于系统安全策略，无需人为事前审批，必须记录扫描证据。

人工封禁与引擎病毒命中分别保留来源、时间和证据。新一次 CLEAN 结果不得自动覆盖未解除的人工封禁；解除封禁走 L3。

### 4.3 重扫与恢复

- 未关联且无安全封禁的文件重扫为 L2；已有相同活动任务时复用，不重复占用扫描资源。
- 现有重扫会使 READY 文件不可用，因此有关联时为 L3。若未来实现不改变可用性的后台复检，应按新状态机重新评审。
- 已拒绝/病毒文件重扫为 L3，因为现有实现可能恢复可用；长期应分离“仅检测”与“解除封禁”，前者不自动放行，后者始终 L3。
- 正常未关联文件恢复为 L2，但只能先进入隔离；SHA256、大小、当前扫描策略、引擎可用性和扫描结果校验通过才允许发布。
- 有安全拒绝历史的恢复必须获得明确的安全解除批准；普通删除恢复审批不能代替解除封禁。历史不足以证明安全状态时按 L3 调查，不推测为安全。
- 已删除文件不能直接重扫；不存在原内容、摘要不符或其他完整性异常时禁止恢复可用，L3 审批也不能豁免。

## 5. 业务上传与下载边界

| 操作 | 目标等级与约束 |
| --- | --- |
| 自己的上传列表、未完成会话、状态、SSE | L0；最小信息、本人及租户边界、连接与请求配额 |
| 发起上传、写分片、完成、终止本人未完成上传 | L1；绑定授权、类型/体积/存储配额、CSRF 防护、限流和幂等；分片无需重复 MFA |
| 正常业务文件下载 | L1；独立业务资源授权，仅 READY+CLEAN、无活动封禁且内容完整的对象可下载 |
| 高敏文件下载或显著批量下载 | 至少 L2，独立授权、配额和审计；审批要求按数据分类策略配置 |
| 病毒样本/被拒绝原文件下载 | 普通下载接口直接禁止；如需研究样本，设计独立 L3 受控导出流程与隔离环境 |

上传和恢复不改变“所有大小统一只读扫描、扫描不复制内容、首次发布不复制内容”的既有约束。存储和 Worker 安全仍遵循 FILE_SECURITY 与扫描历史设计。

## 6. 统一后端决策与防绕过

1. 认证与接口授权后，在租户/数据范围内加载目标和真实引用。由共享文件操作策略解析器计算操作基线、目标风险、组织策略、所选字段风险及禁止条件，控制只能叠加。
2. 不接受客户端提供 riskLevel、requiresApproval、isUnbound 等授权结论。UI 只展示服务端决策，不能成为授权依据。
3. 管理写操作基线最低 L2，按场景升到 L3；不能保留固定 L3 基线再尝试在服务层降级。已有更严格组织策略保留，策略迁移必须显式审查。
4. L2 验证成功后直接原子执行状态变更/入队及审计；L3 先建立目标绑定的申请，再审批执行。扫描仍在事务外由 Worker 执行。
5. L3 申请快照绑定租户、操作、fileId、内容摘要、状态/安全版本、业务引用版本、原因及策略版本。审批只对该目标有效；执行时状态或引用发生变化，拒绝旧申请并重新申请。
6. L2 最终执行事务中重新判定风险。若关联变化使风险升级，返回明确升级结果，不执行任何部分变更；完成 L3 流程后再执行。
7. 文件变更与绑定/解绑统一先锁文件行，再读写引用；业务引用写入也必须遵循该协议。仅删除流程加锁不能防止并发关联绕过。
8. MFA 证明与业务授权分开：五分钟认证新鲜度不能替代目标审批。L3 执行授权绑定请求及快照、一次性消费；幂等重放返回原结果，不能重复执行。
9. 管理员封禁、删除与过期 Worker 使用现有租约及任务 fencing，旧任务不得恢复文件。保留锁定不由审批豁免。
10. 审计记录决策等级、命中规则、策略版本、目标及关联摘要、审批关联、前后状态和结果；写入与变更原子提交。不得记录密码、OTP 或凭证。

未来永久清除必须先确认保留期、调查锁定、引用、对象身份、硬链接、备份和恢复策略；申请删除与后台实际清除均重新检查。只删除一个路径不能视为内容已彻底销毁。

## 7. 开发范围与验收

实现应同时修改风险目录、目标解析器、审批分支、扫描来源模型、封禁来源/解除依据、权限同步及前端反馈；不能只改一个风险常量。

新增风险预检或应急/清除接口时独立登记权限、字段投影及限流；预检同样受目标数据范围约束。写操作返回最小结果，明确“已执行”或“待审批”，不能同样返回空 data 让前端猜测状态。具体 DTO 在 API 开发时同步契约。

至少覆盖以下验收场景：

- 各管理接口的默认等级、敏感字段升级与字段无权时的最小投影。
- 未关联可用文件、未关联病毒文件删除均为 L2；关联文件删除为 L3。
- 保留/调查锁定直接禁止，即使持有 L3 审批也不能执行。
- 预检后新建引用、审批后新增引用、跨租户目标、伪造前端关联信息均不能绕过。
- 关联文件重扫升 L3；拒绝文件重扫不能绕过安全解除审批。
- 人工封禁不能被 CLEAN 覆盖；病毒历史、未知历史恢复按 L3 执行。
- L2 不生成多余审批；L3 无有效独立审批不得执行；MFA 未启用不降级。
- 幂等重放、任务复用、审计失败回滚、删除后旧 Worker 回写、长扫描期间状态变化。
- 批量/应急/永久清除未实现前不暴露入口，已有权限不会隐式获得新增能力。

## 9. 实现、部署与验证范围

已实现：管理读取 L1/敏感字段及审计 L2，四类管理写操作 L2 基线及按真实引用/安全历史升 L3；已有组织操作策略保留。管理操作必须绑定 MFA。业务上传与普通下载调整为 L1。

已实现：文件锁内决策、绑定/解绑遵循同一锁协议、审批目标及配置快照校验、独立安全解除执行人、持久化命令幂等、状态/任务/命令/审计原子提交。普通重扫不解除封禁；明确填写 releaseReason 的 L3 审批执行后，再次扫描 CLEAN 才允许解除和发布。

已实现：securityHold 区分 MANUAL/MALWARE/LEGACY，保存证据时间与原因；删除记录 deletedFromStatus；retentionLocked 阻止删除。旧拒绝/感染记录迁移为 LEGACY，旧删除记录不推测来源。旧文件审批缺少目标快照，必须重新申请。

响应为 `data: { status: 'EXECUTED' | 'PENDING_APPROVAL', riskLevel: 'L2' | 'L3' }`，不返回文件或审批内部对象。页面合并操作原因为一个弹窗，重扫/恢复可明确选择申请安全解除；根据服务器返回状态反馈结果。

文件风险模型现已合并到单一初始化迁移 `20261010000000_initial_security_schema`；原增量迁移已在本地应用的执行事实保留在数据库历史中，本次合并不重写该历史。新库由基线加 seed 完整初始化；旧库切换须遵循 DATABASE_OPERATIONS 的结构、回填与历史验证要求。扫描历史默认字段风险同步仍可使用 `src/scripts/sync-file-risk-fields.ts`，不加参数为预览，`--apply` 更新已存在字段，不授予角色权限、不变更组织操作策略，保留字段 L3 增强配置；本地此前已执行。

验证包含：后端/前端单元测试、两端构建和变更文件 ESLint；真实 MySQL 与 ClamAV 集成测试覆盖未关联正常/病毒文件 L2 删除、持久化幂等、并发关联升级 L3、旧审批快照失效、审计失败回滚、普通 CLEAN 不解除人工封禁、未执行安全解除审批拒绝入队，以及已执行审批加新 CLEAN 才解除封禁。

尚未新增的能力：独立应急隔离、批量删除、永久清除、病毒样本导出、抗钓鱼认证、保留锁定的管理入口。目前这些场景没有新增 API 或授权。数据分类仍仅登记 INTERNAL；普通下载对其他分类明确拒绝，不按 INTERNAL 回退；更高分类的下载与专门授权须随分类模型扩展实现。现有文件引用须继续通过集中绑定服务维护。
