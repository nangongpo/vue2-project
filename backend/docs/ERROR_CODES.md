# API 错误码规范

本文档是 backend 公共错误码的唯一说明。代码目录中的 `backend/src/common/constants/api-code.ts` 是运行时枚举事实；新增、修改或废弃错误码必须先更新代码、测试和本文档，不得复用已发布错误码。

## 1. 错误响应结构

```json
{
  "code": "100003",
  "message": "无权执行此操作",
  "data": {
    "traceId": "server-generated-uuid",
    "status": 403
  }
}
```

字段要求：

- `code`：六位字符串，前导零必须保留；客户端按字符串处理。
- `message`：面向调用方的安全提示，不得包含 SQL、堆栈、文件路径、密钥或内部组件名称。
- `data.traceId`：服务端生成的关联标识，用于客服、审计和日志检索；不得接受客户端 traceId 作为可信值。
- `data.status`：实际 HTTP 状态码。
- `data.details`：仅用于参数错误等可安全公开的字段级提示；不得输出内部异常对象。

## 2. 编码空间

| 范围 | 含义 | 规则 |
| --- | --- | --- |
| `000000` | 成功 | 只用于成功响应 |
| `100xxx` | 客户端、认证、授权、状态和限流错误 | 可按请求修正后重试 |
| `200xxx` | 服务端、数据库和依赖错误 | 不暴露内部细节，记录服务端告警 |
| `9xxxxx` | 预留 | 未经安全评审不得使用 |

业务模块的专用错误码必须在 `100xxx` 或经评审的模块段内登记；禁止随意返回数据库码、异常类名或 HTTP 状态文本作为业务码。

## 3. 当前公共错误码

| 错误码 | 常量 | 默认 HTTP | 含义与处理 |
| --- | --- | ---: | --- |
| `000000` | `SUCCESS` | 2xx | 操作成功 |
| `100001` | `INVALID_PARAMS` | 400 | 参数、格式、枚举、分页或请求体无效；修正请求后重试 |
| `100002` | `UNAUTHORIZED` | 401 | 未登录、会话过期或认证失败；重新认证 |
| `100003` | `FORBIDDEN` | 403 | 无权限、CSRF、数据范围或安全策略拒绝；不得盲目重试 |
| `100004` | `NOT_FOUND` | 404 | 资源不存在或按安全策略隐藏资源存在性 |
| `100005` | `CONFLICT` | 409 | 状态、版本、唯一性或并发冲突；刷新资源后处理 |
| `100006` | `RATE_LIMITED` | 429 | 请求频率超限；按 `Retry-After` 或退避策略重试 |
| `100007` | `CAPTCHA_REQUIRED` | 400/403 | 需要完成行为验证码 |
| `100008` | `CAPTCHA_INVALID` | 400 | 验证码无效、过期或已消费 |
| `100009` | `REQUEST_IN_PROGRESS` | 409 | 相同幂等请求仍在处理；查询原请求状态 |
| `100010` | `MFA_REQUIRED` | 200/401 | 登录流程需要 MFA；仅返回下一步所需安全信息 |
| `100011` | `MFA_INVALID` | 401/403 | MFA 验证失败、过期或重放 |
| `100012` | `MFA_ENROLL_REQUIRED` | 200/403 | 必须先完成 MFA 注册 |
| `100013` | `SECURITY_STEP_UP_REQUIRED` | 403 | 高风险操作需要最近 MFA、重新认证或审批 |
| `200000` | `INTERNAL_ERROR` | 500 | 未分类服务端错误；客户端不得重试写操作 |
| `200001` | `DATABASE_ERROR` | 503 | 数据服务异常；服务端告警，客户端按接口安全策略退避 |
| `200002` | `SERVICE_UNAVAILABLE` | 503 | Redis、验证码、扫描或其他依赖不可用 |

`MFA_REQUIRED`、`MFA_ENROLL_REQUIRED` 在登录流程中可以使用 HTTP 200 表示“需要下一步”，不能把它当作完整登录成功；其他认证失败应使用对应 401/403 语义。

## 4. HTTP 映射

公共异常过滤器按以下规则映射未显式指定业务码的异常：

| HTTP 状态 | 默认错误码 |
| ---: | --- |
| 400 | `100001 INVALID_PARAMS` |
| 401 | `100002 UNAUTHORIZED` |
| 403 | `100003 FORBIDDEN` |
| 404 | `100004 NOT_FOUND` |
| 409 | `100005 CONFLICT` |
| 413/415 等请求格式错误 | `100001 INVALID_PARAMS` |
| 429 | `100006 RATE_LIMITED` |
| 500 | `200000 INTERNAL_ERROR` |
| 503 | `200002 SERVICE_UNAVAILABLE` |

数据库错误在服务端记录原始错误和 traceId，但对外统一为 `200001 DATABASE_ERROR` 或按依赖不可用策略返回 `200002 SERVICE_UNAVAILABLE`。

## 5. 安全和脱敏规则

- 对外错误不得暴露 Prisma `Pxxxx`、SQL、表名、列名、文件路径、对象 Key、ClamAV 协议、Node/Nest/Fastify 堆栈或密钥。
- 登录、密码、MFA、验证码、租户、文件和权限错误不能通过消息差异泄露账号、资源、租户或文件是否存在。
- 生产环境 5xx 使用固定安全消息；详细异常只进入受保护的服务端日志和审计告警。
- `details` 只能包含字段名、允许范围、枚举值或安全操作提示；不得回显密码、Token、Cookie、上传内容或完整请求体。
- 错误审计必须记录 traceId、主体、租户、资源、动作、HTTP 状态、错误码、结果和拒绝原因，但同样执行敏感字段脱敏。
- Redis、数据库、验证码、ClamAV 或对象存储不可用时默认拒绝高风险操作，不得降级为放行或“扫描成功”。

## 6. 客户端处理

- `100002`：清除失效会话并跳转登录；
- `100010` / `100012`：进入登录 MFA 或注册流程；
- `100011`：提示重新输入或重新获取认证因素，但不能无限重试；
- `100013`：按 `data.requiredFactors` 完成安全升级，不得绕过；
- `100005` / `100009`：重新查询资源或任务状态，禁止盲目重复写入；
- `100006`：遵守退避和服务端限流提示；
- `200xxx`：展示通用不可用提示，写请求只有在接口明确幂等时才可重试。

## 7. 变更与测试

新增错误码必须同时完成：

1. 更新 `api-code.ts` 的常量、标题和安全消息；
2. 明确 HTTP 状态、客户端动作、审计字段和是否允许重试；
3. 增加公共错误码契约测试和至少一个真实 HTTP 测试；
4. 检查 5xx 脱敏、跨租户错误一致性、traceId 关联和日志脱敏；
5. 更新 API/OpenAPI 文档和对应业务契约。

禁止删除或重用已发布错误码；废弃码保留历史映射，新增语义使用新编码。
