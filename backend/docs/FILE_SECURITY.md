# 文件模块安全需求

## 1. 目的和适用范围

本文档是文件模块的唯一业务、安全和验收依据，适用于：

- 业务页面上传、分片上传和断点续传；
- 文件最终化、病毒扫描和安全状态管理；
- 文件查询、下载、删除、恢复和重新扫描；
- SSE 状态通知及轮询兜底；
- 租户、组织、部门、数据范围和字段权限控制；
- 审批、审计、任务恢复和多实例部署。

设计要求以等保三级为基线，按高安全场景实施。所有未通过授权、完整性校验、病毒扫描、数据范围校验或审计要求的操作，默认拒绝。

本文档中的“必须”是强制要求。实现不得通过隐藏前端按钮、延长 HTTP 请求、使用兼容分支或绕过服务端校验来替代安全控制。

## 2. 安全原则

1. 文件在通过最终化和安全扫描前，不得下载、绑定业务或被业务使用。
2. 每次请求都必须重新校验登录态、租户、组织、部门、数据范围和资源权限。
3. `uploadId`、`fileId`、对象 Key、任务 ID 和文件哈希都不是授权凭证。
4. 文件名、扩展名、声明 MIME、客户端哈希和请求参数均为不可信输入。
5. 系统管理权限不自动授予业务文件查看、下载或修改权限。
6. 扫描服务、任务队列、审计服务或存储服务异常时，文件保持不可用。
7. 前端只负责展示和传输，不能决定文件状态、权限、数据范围或可用动作。
8. 所有状态变化、权限拒绝、任务失败和管理操作都必须可审计、可追踪、可恢复。

## 3. 模块职责

### 3.1 文件模块

负责上传会话、分片接收、分片校验、最终化任务、病毒扫描任务、文件状态、隔离存储、清理补偿、权限前置校验和安全审计。

### 3.2 业务模块

负责业务用途、业务资源、允许的文件字段、业务对象存在性、业务绑定关系和业务授权。业务模块不得直接修改文件状态、扫描结果或物理存储位置。

### 3.3 系统文件管理

负责按系统权限和数据范围查看文件安全元数据、查看任务、发起审批、查看告警和执行获批操作。系统文件管理权限不得绕过业务文件下载权限。

### 3.4 Worker 和事件模块

Worker 负责最终化、扫描、重试、超时恢复和清理。事件模块负责通过 Outbox、Redis 和 SSE 发布状态通知。事件通知失败不得回滚已经提交的业务状态。

## 4. 数据隔离模型

文件访问必须同时满足以下四层约束：

```text
租户
  → 组织
    → 部门
      → 数据资源 / 行级数据范围 / 字段权限
```

### 4.1 租户

- 文件、上传会话、分片、任务、业务绑定和审计记录必须带有 `tenantId`。
- 所有查询、写入、下载、任务执行和事件推送必须先限制在当前会话租户内。
- 单租户模式也必须执行租户条件，不能因为只有默认租户而省略校验。

### 4.2 组织和部门

- 业务账号必须绑定初始化的默认组织和默认部门；未来启用组织和部门时直接使用同一模型。
- 平台管理账号属于 `PLATFORM` 管理域，不因 `organizationId` 或 `departmentId` 为空而获得业务文件范围。
- `organizationId = NULL`、`departmentId = NULL` 不表示全部组织或全部部门。
- 组织或部门为空时，不能扩大数据范围；无法确定有效范围时必须拒绝。

### 4.3 数据资源和字段权限

数据资源权限决定能否访问接口和资源；行级数据范围决定能看到哪些文件；字段权限决定响应中能看到哪些字段。三者必须同时通过。

行级过滤先于字段裁剪：

```text
认证
→ 租户过滤
→ 组织/部门过滤
→ 行级数据范围过滤
→ 资源权限校验
→ 字段权限裁剪
→ 返回响应
```

字段权限不能扩大行级范围，接口查询参数不能覆盖服务端计算出的 `tenantId`、`ownerUserId`、`organizationId` 或 `departmentId`。

支持的数据范围：

```text
SELF                  当前用户本人资源
DEPARTMENT_SELF       当前部门资源
DEPARTMENT_TREE       当前部门及下级部门资源
ORGANIZATION_SELF     当前组织资源
ORGANIZATION_TREE     当前组织及下级组织资源
TENANT                当前租户资源
CUSTOM                经授权的明确资源集合
```

未配置或无法解析数据范围时默认拒绝，不得自动回退为 `SELF` 或全量范围。

## 5. 文件状态

### 5.1 上传会话状态

```text
UPLOADING
  → FINALIZING
  → SCANNING
  → COMPLETED

UPLOADING  → ABORTED / EXPIRED / FAILED
FINALIZING → FAILED / EXPIRED
SCANNING   → FAILED / EXPIRED
```

### 5.2 文件安全状态

| 文件状态 | 扫描状态 | 是否允许业务使用 |
| --- | --- | --- |
| `QUARANTINED` | `PENDING`、`RUNNING`、`ERROR` | 否 |
| `QUARANTINED` | `CLEAN` | 否，等待转正完成 |
| `REJECTED` | `INFECTED` 或其他拒绝结果 | 否 |
| `READY` | `CLEAN` | 是，但仍需通过访问权限和数据范围 |
| `DELETED` | 任意 | 否 |

只有 `READY + CLEAN` 且当前请求通过完整授权时，才允许下载或绑定业务。

### 5.3 任务状态

```text
PENDING → RUNNING → SUCCEEDED
                  → INFECTED
                  → FAILED → PENDING
                  → DEAD_LETTER
PENDING/RUNNING → CANCELLED
```

任务必须具有租约、重试次数、下次执行时间和超时恢复机制。进程重启、实例故障或 Redis 故障不得导致任务丢失。

## 6. 上传接口和流程

### 6.1 创建上传会话

```http
POST /api/v1/files/uploads/initiate
```

服务端必须校验：

- 当前登录态和当前租户；
- 业务用途、业务资源和目标字段；
- 用户、组织、部门和数据范围；
- 文件大小、文件数量、用户配额和并发限制；
- 允许的扩展名、声明 MIME 和业务策略；
- 幂等键、重新认证、MFA 和审计要求。

服务端生成并返回 `uploadId`、`chunkSize`、`totalParts` 和 `expiresAt`。分片大小、分片数量和有效期由服务端决定，客户端不能覆盖。

服务端不得信任客户端提交的 MIME、扩展名、哈希、物理路径或任意权限字段。

### 6.2 查询上传状态

```http
GET /api/v1/files/uploads/:uploadId/status
```

每次请求必须重新校验当前用户、租户、会话归属、会话状态、有效期和权限。仅返回：

- 已接收分片编号；
- 上传会话状态；
- 文件和扫描安全状态；
- 是否允许继续、完成或重试；
- 客户端需要展示的安全错误。

不得返回对象 Key、物理路径、任务锁、内部堆栈、扫描协议原文或数据库错误。

### 6.3 上传分片

```http
PUT /api/v1/files/uploads/:uploadId/parts/:partNumber
```

服务端必须校验登录态、接口权限、会话归属、租户、会话状态、分片编号、请求体大小、分片大小和并发限制。分片只能写入隔离区。

分片以 `(uploadSessionId, partNumber)` 唯一。重复提交同一分片必须幂等；不同内容不得覆盖已经确认的分片，必须返回冲突并记录审计。

### 6.4 提交完成

```http
POST /api/v1/files/uploads/:uploadId/complete
```

接口只执行以下操作：

1. 校验分片完整且连续；
2. 使用条件更新将会话从 `UPLOADING` 改为 `FINALIZING`；
3. 创建文件记录和最终化任务；
4. 返回异步任务和安全状态。

接口不得等待文件合并、类型检测或病毒扫描。重复调用必须返回已有任务状态，不得重复创建任务。

示例响应：

```json
{
  "code": "000000",
  "message": "上传已提交，文件正在处理中",
  "data": {
    "uploadId": "uuid",
    "fileId": "uuid",
    "uploadStatus": "FINALIZING",
    "fileStatus": "QUARANTINED",
    "scanStatus": "PENDING"
  }
}
```

### 6.5 中止上传

```http
POST /api/v1/files/uploads/:uploadId/abort
```

仅允许当前会话所属用户或经明确授权的管理角色中止未最终化会话。分片清理失败时必须创建可重试的清理任务，不能静默忽略。

## 7. 安全断点续传

断点续传的授权主体是服务端上传会话。`uploadId` 仅用于定位会话，不是权限凭证。

### 7.1 当前页面内续传

```text
查询服务端已接收分片
→ 校验当前用户、租户、会话和权限
→ 只上传缺失分片
→ 幂等提交 complete
```

### 7.2 刷新或重新打开页面

浏览器本地存储不是恢复前提，不依赖 IndexedDB、localStorage 或其他持久化能力。服务端必须提供以下接口查询当前用户的未完成会话：

```http
GET /api/v1/files/uploads/unfinished
```

服务端必须提供“当前用户未完成上传”查询能力，恢复流程如下：

1. 当前用户完成重新认证并查询自己的未完成会话；
2. 用户重新选择原文件；
3. 服务端校验文件大小、客户端哈希、会话用户、租户、组织、部门、有效期和文件状态；
4. 服务端返回已接收分片，客户端只补传缺失分片；
5. 任一校验失败、会话过期或状态不允许继续时，创建新会话，不得强行复用旧会话。

`sessionStorage` 只能保存非敏感展示线索，不能作为授权依据。不得把访问令牌、Cookie、对象存储凭证、对象 Key 或可独立授权的恢复信息写入浏览器存储。

## 8. 最终化和病毒扫描

### 8.1 最终化 Worker

Worker 获取并锁定 `FINALIZING` 任务后，必须：

1. 在隔离区流式合并分片；
2. 重新计算服务端 SHA-256；
3. 进行魔数、实际 MIME 和扩展名检测；
4. 校验客户端哈希；
5. 创建扫描任务并将文件置为 `SCANNING`。

不得把完整文件加载到内存。临时对象完成后必须原子提交，失败时进入补偿清理。

### 8.2 扫描 Worker

扫描 Worker 必须从隔离区读取文件，通过受控的本地 Unix Socket 或内网 TCP 调用 `clamd`，保存扫描结果、病毒库版本、引擎版本和策略版本。

扫描不能在 HTTP 请求或审批事务中执行。禁止使用未持久化的后台 Promise 代替任务记录。

扫描服务不可用、病毒库过期、超时、结果不确定或审计失败时，文件保持隔离，不得转为 `READY`。

## 9. SSE 状态通知和轮询

SSE 只负责通知，不负责推进状态，也不是真实状态来源。真实状态始终以服务端状态查询为准。

```http
GET /api/v1/files/uploads/:uploadId/events
```

要求：

- 只允许同源连接，并重新校验当前登录态、用户、租户、会话和权限；
- 发送当前状态快照和最小状态变化事件；
- 不发送文件内容、对象 Key、扫描协议或敏感字段；
- 通过 Outbox 保证数据库状态与事件记录一致；
- 通过 Redis 支持多实例发布；
- Redis、SSE 或 EventSource 不可用时，自动切换状态接口轮询；
- SSE 和轮询都不能修改上传状态；
- 进入终态后关闭 SSE、轮询定时器和页面监听器。

轮询是实时通知失败时的兜底机制，不得因 SSE 失败而让上传任务失败。详细连接治理和多实例要求见 [SSE_DESIGN.md](SSE_DESIGN.md)。

## 10. 系统文件管理

### 10.1 查询

```http
GET /api/v1/files
GET /api/v1/files/:fileId
```

必须按系统权限、租户、组织、部门、行级数据范围和字段权限过滤。列表和详情使用独立字段策略，不得因为列表可见就默认返回全部安全字段。

服务端计算并返回 `availableActions`。前端不能自行根据状态、角色名称或固定中文文案判断按钮。

### 10.2 重新扫描、拒绝、删除和恢复

```http
POST /api/v1/files/:fileId/rescan
POST /api/v1/files/:fileId/reject
POST /api/v1/files/:fileId/delete
POST /api/v1/files/:fileId/restore
```

高风险操作统一采用：

```text
申请 → 审批 → 执行 → 复核
```

申请人不得审批自己的申请，审批、执行和复核人员不得违反职责分离要求。恢复后的文件必须重新进入隔离和扫描，不得直接恢复为 `READY`。

执行阶段只提交状态变化和持久化任务，不执行长时间文件 IO。

## 11. 权限和字段控制

### 11.1 业务权限

| 权限 | 用途 | 要求 |
| --- | --- | --- |
| `file.upload.read` | 上传页面基础查询 | 必须通过租户和数据范围 |
| `file.upload.resume` | 查询本人未完成会话 | 仅当前用户、当前租户、当前组织和当前部门 |
| `file.upload.status` | 查询上传状态 | 会话绑定当前用户 |
| `file.upload.events` | 接收状态通知 | 仅通知，不改变状态 |
| `file.upload.initiate` | 创建上传会话 | 重新认证、MFA、限流、幂等、审计 |
| `file.upload.part` | 上传分片 | 会话绑定、大小校验、限流 |
| `file.upload.complete` | 提交完成 | 条件更新、幂等、审计 |
| `file.upload.abort` | 中止会话 | 归属校验、状态校验、审计 |
| `file.download` | 下载文件 | 必须额外通过文件状态和数据范围 |

### 11.2 系统权限

```text
system.file.admin.read
system.file.admin.detail
system.file.admin.task.read
system.file.admin.scan
system.file.admin.reject
system.file.admin.delete
system.file.admin.restore
system.file.admin.download
```

系统权限只决定允许执行的管理动作，不能跳过租户、组织、部门、数据范围、字段权限和业务下载条件。

### 11.3 字段权限

至少区分以下字段：文件名、上传人、文件大小、哈希、业务绑定、扫描状态、扫描详情、扫描引擎版本、任务错误和审计信息。

响应必须由服务端按字段权限裁剪。内部路径、对象 Key、扫描协议、数据库错误、堆栈和凭证永远不得返回。

## 12. 存储和内容安全

1. 文件物理路径和对象 Key 使用服务端生成的随机标识，禁止拼接用户输入。
2. 隔离区、正式对象区、备份区和扫描区必须分离，并使用最小权限账号。
3. 上传目录禁止执行权限，正式对象存储必须私有化。
4. 必须限制单文件大小、分片数量、用户配额、并发数、压缩包递归层数和解压大小。
5. 文件只有 `READY + CLEAN` 才能进入正式可用对象区。
6. 过期、中止、失败和孤儿对象必须由可重试、可审计的清理任务处理。
7. ClamAV 只能通过受控的 Unix Socket 或内网 TCP 访问，3310 端口不得暴露到业务网以外。

## 13. 幂等、并发和补偿

1. `initiate` 使用客户端幂等键，避免重复创建上传会话。
2. `complete` 使用数据库条件更新，只允许一个请求抢占最终化。
3. 重复 `complete` 返回已有任务状态，不重复合并或扫描。
4. 分片按会话和编号幂等；不同内容的重复分片必须拒绝。
5. Worker 使用锁和租约，锁超时后由其他实例恢复。
6. 状态迁移只能由服务端状态机完成，前端不能提交状态字段。
7. 扫描结果必须绑定文件 ID、文件哈希和任务 ID，旧任务不能覆盖新结果。
8. 业务状态和状态事件必须在同一数据库事务中写入；事件发布失败由 Outbox 重试。
9. 数据库、对象存储和任务状态不一致时，进入补偿任务并告警。

## 14. 审计、错误和告警

### 14.1 审计事件

至少记录：创建会话、分片异常、完成提交、最终化、扫描、状态变化、绑定/解绑、下载成功和拒绝、审批申请/审批/执行/复核、管理员敏感查询和清理任务。

审计至少包含事件 ID、时间、租户、操作者、会话、源 IP、请求 ID、文件 ID、业务资源、动作、结果、风险等级、策略版本和拒绝原因。

不得记录密码、OTP、Cookie、上传凭证、文件原文、完整下载地址、对象存储凭证、扫描协议原文、数据库错误或堆栈。

### 14.2 错误响应

统一使用系统错误信封，不能暴露框架、数据库、文件系统、ClamAV、物理路径或内部任务信息。异步接口必须返回安全状态、任务状态和是否允许重试。

### 14.3 告警

至少监控扫描积压、病毒命中、任务反复失败、跨租户访问、异常上传、存储不足、审计失败、对象与元数据不一致和大量权限拒绝。

## 15. 数据模型最低要求

### 15.1 文件

```text
id, tenant_id, organization_id, department_id, owner_user_id
storage_key, original_name, safe_name
declared_mime, detected_mime, extension, size, sha256
status, scan_status, scan_detail
scan_engine_version, policy_version
created_at, updated_at, deleted_at
```

`storage_key` 和物理存储信息仅在服务端保存。

### 15.2 上传会话

```text
id, tenant_id, organization_id, department_id, user_id, file_id
object_key, file_name, declared_mime, purpose
resource_type, resource_id, field_name
file_size, chunk_size, total_parts, client_sha256
status, expires_at, created_at, updated_at
```

上传会话必须绑定租户、组织、部门、用户、业务用途和目标资源。

### 15.3 分片和任务

分片以 `(upload_session_id, part_number)` 唯一，至少保存大小、校验和、状态和时间。

任务至少保存：

```text
id, file_id, upload_id, tenant_id, status
attempts, max_attempts, next_retry_at
locked_at, locked_by, started_at, finished_at
last_error, created_at, updated_at
```

任务表必须支持按状态、租户、下一次执行时间和锁超时恢复。

## 16. 测试和验收

### 16.1 功能

- 乱序、并发、重复分片、单片重试和断点续传；
- 页面刷新后通过服务端未完成会话恢复；
- 错误文件、错误用户、错误租户、错误组织、错误部门和过期会话被拒绝；
- 重复 `complete`、网络中断、进程重启和任务恢复；
- 最终化成功、失败、超时和孤儿对象清理；
- 扫描通过、病毒命中、扫描服务不可用和病毒库过期；
- EventSource 不可用、SSE 失败、Redis 不可用和轮询兜底；
- 终态关闭 SSE、轮询定时器和页面监听器。

### 16.2 安全

- 越权访问其他用户、租户、组织和部门文件；
- 篡改 `fileId`、`uploadId`、`partNumber`、文件哈希和业务资源；
- 路径穿越、控制字符、伪造 MIME、恶意压缩包和超大请求；
- 重放幂等键、过期会话、旧扫描任务和并发状态变更；
- 下载未扫描文件或状态不确定文件；
- 系统权限绕过业务下载权限；
- 申请人审批自己或违反职责分离；
- 泄露内部路径、对象 Key、扫描协议、数据库错误或堆栈。

### 16.3 权限和字段

每个接口必须验证统一响应、资源权限、租户条件、组织/部门条件、行级数据范围、字段裁剪、服务端 `availableActions`、业务/系统边界和审计记录。

## 17. 结论

文件必须严格经过以下流程：

```text
授权创建上传会话
→ 隔离区接收分片
→ 校验完整性并提交最终化任务
→ 服务端合并、计算哈希、检测实际类型
→ 病毒扫描和安全策略检查
→ CLEAN + READY
→ 每次访问重新校验权限和数据范围
```

任一环节失败、超时、结果不确定或无法审计时，文件保持不可用，任务进入可恢复的失败或隔离状态。
