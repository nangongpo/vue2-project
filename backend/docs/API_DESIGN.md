# API 接口设计规范

本文档定义 backend 对外 HTTP API 的公共规范。业务模块只定义资源、权限和业务字段；审批接口以 [APPROVAL_CONTRACT.md](APPROVAL_CONTRACT.md) 为准，文件接口以 [FILE_SECURITY.md](FILE_SECURITY.md) 为准，租户上下文以 [TENANCY_SECURITY.md](TENANCY_SECURITY.md) 为准。

## 1. 基本原则

- 所有业务 API 使用 `/api/v1` 前缀；健康检查和 Swagger 等基础设施端点由部署策略单独保护。
- 后端是唯一安全边界。前端路由、按钮隐藏、请求参数和客户端租户标识都不能替代服务端鉴权。
- 默认拒绝、显式授权、租户上下文固定、数据范围过滤和字段裁剪必须在服务端完成。
- 请求、响应、错误、审计和 traceId 采用稳定结构；不得把内部异常、SQL、物理路径、对象 Key、密钥或堆栈返回客户端。
- 新接口必须具备 DTO 类型校验、权限目录登记、审计策略、风险等级和正反向测试。

## 2. URL、方法和资源

### 2.1 路径

- 使用资源名复数：`/users`、`/roles`、`/files`。
- 子资源使用父资源标识：`/roles/:id/grants`。
- 动作使用明确的动词后缀：`/users/:id/enable`、`/files/:id/rescan`；不得使用含义不清的 `/manage`、`/process`。
- 标识使用 UUID 或服务端定义的稳定标识；禁止把数据库自增内部 ID 直接作为公开资源标识。
- 路径参数必须使用专用 Pipe/DTO 校验，禁止将未校验字符串直接拼接查询条件或文件路径。

### 2.2 HTTP 方法

| 方法 | 用途 | 约束 |
| --- | --- | --- |
| `GET` | 查询、详情、选项 | 不改变业务状态；仍需认证、权限、租户和数据范围校验 |
| `POST` | 创建或执行明确动作 | 创建返回 `201`；高风险动作必须审批或重新认证 |
| `PUT` | 完整替换资源或上传分片 | 必须定义幂等和覆盖语义 |
| `PATCH` | 部分更新 | 只允许 DTO 白名单字段，字段权限单独校验 |
| `DELETE` | 删除或撤销 | 默认逻辑删除/状态转换；有引用或审计保留要求时拒绝物理删除 |

禁止使用 `GET` 执行写操作，禁止用客户端提交的 `status` 直接跳过服务端状态机。

## 3. 请求规范

### 3.1 Headers

```http
Accept: application/json
Content-Type: application/json
X-Request-Trace-Id: server-generated
Idempotency-Key: client-generated-unique-key
```

- Cookie 会话请求必须通过 CSRF Origin 校验；状态变更请求不得仅依赖 Referer。
- `X-Request-Trace-Id` 由服务端生成并通过响应头返回，客户端提供的同名值不得作为可信 traceId。
- `Idempotency-Key` 使用标准名称，不通过“隐藏名称”获得安全性；服务端必须将接口范围、认证主体、租户、请求摘要和 Key 绑定，不能只按 Key 全局复用。
- 文件上传使用 `application/octet-stream`，大小、分片编号、会话归属和哈希由服务端重新校验。

### 3.2 JSON 字段

- 公共 JSON 使用 camelCase；数据库 snake_case 不得直接泄露为 API 字段。
- 必填字段不能用 `null`、空字符串或隐式默认值绕过业务校验。
- 枚举、长度、格式、数字范围、分页和排序字段必须通过 DTO 校验。
- 不接受 DTO 外字段，尤其拒绝 `tenantId`、`ownerId`、`roleType`、`status`、`permissionIds` 等可能改变安全边界的客户端字段，除非该字段在专用契约中明确允许。
- 服务器生成的 `createdAt`、`updatedAt`、审计主体、租户归属、权限结果和状态转换不得由客户端提交覆盖。

## 4. 认证、授权和租户

每次请求的允许条件至少是：

```text
认证会话有效
AND 用户、角色和授权关系有效
AND API 方法与路径精确匹配
AND 权限资源为 ACTIVE
AND 当前租户上下文有效
AND 资源位于允许的数据范围
AND 请求字段通过字段权限校验
AND 风险操作满足 MFA/重新认证/审批要求
```

- 单租户也必须绑定明确默认租户；不得使用空租户表示公共范围。
- 多租户请求只使用服务端会话中的 active tenant；不得信任 query、body、header 或前端路由中的租户值。
- 列表、详情、导出、下载、选项和批量接口必须分别执行数据范围校验，不能从列表权限推导详情或导出权限。
- 失败时默认拒绝；权限、缓存、租户或审计服务不可用时不能降级放行。

## 5. 成功响应

除明确声明 `204 No Content` 的接口外，成功响应统一为：

```json
{
  "code": "000000",
  "message": "success",
  "data": {}
}
```

分页响应：

```json
{
  "code": "000000",
  "message": "success",
  "data": {
    "items": [],
    "total": 0,
    "page": 1,
    "pageSize": 10,
    "totalPages": 0
  }
}
```

分页要求：`page >= 1`，`1 <= pageSize <= 100`；排序字段必须使用服务端白名单，不能直接拼接客户端传入的 SQL 字段。

创建资源返回 `201`；异步创建、文件最终化、扫描和长时间任务返回 `202` 或明确的成功状态，不得在 HTTP 请求中无限等待。

## 6. 错误响应

错误统一使用：

```json
{
  "code": "100003",
  "message": "无权执行此操作",
  "data": {
    "traceId": "server-generated-uuid",
    "status": 403
  }
}
```

参数校验可增加 `details`，但只返回字段名和可操作提示，不返回 SQL、堆栈、内部模型、密钥或文件路径。错误码的完整目录、HTTP 映射和脱敏规则见 [ERROR_CODES.md](ERROR_CODES.md)。

## 7. 幂等、并发和状态

- 创建、提交、审批、执行、上传完成、扫描和状态变更必须定义幂等键或条件更新。
- 重复请求返回当前安全状态，不能重复扣减、重复授权、重复执行脚本或重复发送副作用。
- 资源状态转换由服务端白名单定义；非法迁移返回 `100005`。
- 并发认领、版本冲突和重复执行必须返回冲突，不可静默覆盖。
- 数据库写入、审计写入和关键状态转换必须在同一事务或具备可验证的补偿机制。

### 7.1 当前完整幂等接口范围

下列业务写接口由幂等守卫强制要求 `Idempotency-Key`，采用完整幂等模式：绑定请求主体指纹，并在成功响应窗口内保存首次响应；其他接口不要求该请求头：

- 用户、角色、权限目录、权限 API、按钮、字段和数据范围的创建、修改、启停、删除、授权和撤销；
- 审批申请、审批、执行、复核和取消；
- 运维工单创建、修改、提交、审批、执行、复核、取消、证据和执行记录追加；
- 文件上传会话创建/完成/中止，以及文件拒绝、删除、恢复和重新扫描；
- 密码修改、租户切换和其他业务状态变更。

登录、MFA 注册/确认/重新认证、会话续签要求 `Idempotency-Key`，采用短时锁模式：只防止同一请求并发执行，不绑定长期指纹，也不缓存响应，因为它们涉及一次性认证因素或 Cookie 副作用。登出、验证码接口、健康检查、查询接口和静态资源不要求该请求头。文件分片上传使用分片号天然幂等，不要求通用幂等 Key。

前端 `sendRequest` 会为写请求生成安全随机 Key，并在 Axios 重试时复用同一个请求配置中的 Key。需要让用户重复点击仍复用同一业务操作时，调用方必须在业务动作开始时生成 Key，并通过 `idempotencyKey` 配置传入；不能每次点击都生成新的业务操作 Key。

## 8. 字段、文件和导出

- 响应只返回调用方有字段读取权限的字段；敏感字段默认不返回。
- 写入只允许 DTO 和字段权限共同允许的字段；未知字段直接拒绝。
- 文件下载必须重新鉴权、校验租户和数据范围，使用短期凭证或受控流；不得返回永久公开 URL。
- 导出是独立权限，必须限制范围、字段、数量和频率，并记录审计。
- 业务对象不存在、无权访问和跨租户资源不得通过差异化错误消息泄露敏感存在性；按安全策略返回统一结果。

## 9. 审计和可观测性

每个请求都应具备服务端 traceId。登录、认证失败、权限拒绝、租户切换、敏感查询、导出、文件操作、审批、配置和密钥操作必须产生审计事件。

审计至少包含主体、租户、资源、动作、结果、HTTP 状态、来源 IP、User-Agent、时间、traceId 和拒绝原因。日志不得写入密码、MFA 秘密、Cookie、Session Token、完整下载地址、文件原文和数据库堆栈。

## 10. 版本和变更

- 破坏性变更升级 API 主版本或建立新资源路径，不修改旧接口语义后要求客户端猜测。
- 新增字段默认向后兼容，但敏感字段必须走字段权限和安全评审。
- 错误码一经发布不得复用；废弃码保留历史含义并标记 retired。
- 修改路径、方法、权限码、状态机、租户边界或响应字段必须同步更新权限目录、审计策略、测试和对应业务契约。

## 11. 验收清单

- 未认证、无权限、过期授权、禁用资源、跨租户和越数据范围均拒绝；
- DTO 类型、长度、枚举、分页、排序和未知字段测试通过；
- 成功和失败响应包含统一 code/message/data，内部异常已脱敏；
- traceId 不能被客户端伪造，错误审计可关联；
- 幂等、重放、并发冲突、状态机和事务补偿测试通过；
- 字段裁剪、下载、导出、日志脱敏和敏感字段扫描通过；
- OpenAPI/Swagger 与实际路由、方法、权限和响应契约一致。
